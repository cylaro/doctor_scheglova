# Тест о гормональных изменениях

Адаптивный сайт на русском языке: пять вопросов, персональный результат, справочные страницы о трех периодах и контакты специалиста. Бирюзовая палитра, локальные шрифты, без регистрации и серверной части.

## Запуск

Нужен Node.js **22.12 или новее**. Откройте терминал в папке проекта:

```sh
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. Для проверки готовой сборки:

```sh
npm test
npm run build
npm run preview
```

Предпросмотр доступен по `http://127.0.0.1:4173`. Остановить сервер можно сочетанием `Ctrl+C`. Открытие `index.html` двойным щелчком не поддерживается: сайту нужен HTTP-сервер.

## Ваши данные и фотография

Все личные данные редактируются в **[public/site-config.js](public/site-config.js)**. Их не нужно отправлять в чат. Любое поле можно оставить пустым (`''`) или удалить целиком. Блоки `doctor` и `contacts` тоже можно удалить: тест продолжит работать. Сохраняйте корректные запятые и скобки JavaScript. Файл должен быть в UTF-8. Если в значении нужна одинарная кавычка, экранируйте ее: `\'`.

| Поле | Что указать |
| --- | --- |
| `brandName` | Название сайта или проекта. Используется и при незаполненном имени врача. |
| `doctor.name` | Имя и фамилия специалиста. |
| `doctor.specialty` | Специальность. |
| `doctor.description` | Короткое описание: квалификация, опыт или подход. |
| `doctor.avatar` | Путь к фотографии. Сейчас `doctor.jpg` соответствует файлу `public/doctor.jpg`. |
| `contacts.phone` | Телефон с кодом страны, например `+7 (999) 123-45-67`. |
| `contacts.telegram` | Полная ссылка вида `https://t.me/your_username`. |
| `contacts.telegramLabel` | Подпись ссылки: `Telegram` или ваш `@username`. |
| `contacts.whatsapp` | Ссылка вида `https://wa.me/79991234567`, номер без пробелов и плюса. |
| `contacts.email` | Адрес электронной почты. |
| `contacts.bookingLinks` | Список мест записи: для каждого задайте `label`, `url` и необязательный `description`. |
| `contacts.bookingUrl` | Старый формат одной HTTPS-ссылки тоже поддерживается; он добавляется к списку без повторов. |
| `contacts.address` | Адрес клиники, если нужен. |
| `siteUrl` | Полный публичный адрес этого сайта, например `https://example.ru/test/`, без `#`. Необязательно; используется для ссылки «Поделиться тестом» и канонического адреса страницы. |

Удаленные или пустые поля врача и контактов скрываются. Без имени врача в шапке используется название проекта; в карточку врача вымышленные имя и специальность не подставляются. Если все данные удалены, пустой блок не выводится. Удаление `telegramLabel` оставляет обычную подпись «Telegram».

При одной ссылке кнопка «Записаться» в шапке сразу открывает запись. При нескольких она открывает компактный выбор места приёма. На главной странице ссылки также видны рядом с карточкой врача, а на странице результата — в блоке консультации. Если ссылок записи нет, кнопка «Связаться» использует первый доступный контакт: телефон, Telegram, WhatsApp, email. Если и контактов нет, кнопка скрывается.

Чтобы добавить несколько ссылок, используйте список внутри `contacts`:

```js
bookingLinks: [
  {
    label: 'Клиника «Огни»',
    url: 'https://ogni.clinic/doctors/shcheglova_svetlana_vyacheslavovna',
  },
  // Для следующего места скопируйте блок {...} и замените название и ссылку.
],
```

У каждого варианта можно добавить `description: 'Адрес или формат приёма'`. Порядок на сайте соответствует порядку в списке. Без `label` показывается домен ссылки. Без корректного `url` вариант скрывается. Повторяющиеся ссылки не дублируются. Используйте обычные URL (`https://...`), без оформления `[текст](ссылка)`. Все места записи попадают и в сохраняемый результат.

Настройки используются на всех экранах сайта. Контактные данные в сохраняемом результате берутся из того же файла, поэтому дублировать изменения в коде не нужно. Этот файл публичный: указывайте только данные, которые готовы разместить на сайте, без паролей и секретных ключей.

Чтобы добавить аватарку:

1. Положите квадратную фотографию, желательно от 400 × 400 пикселей, в `public/doctor.jpg`.
2. Укажите `avatar: 'doctor.jpg'` в разделе `doctor` файла настроек.
3. Обновите страницу. Фото автоматически обрежется по кругу. При пустом или удаленном `avatar` место под фото не выводится; при ошибке загрузки указанного файла остается нейтральный значок.

JPG, PNG и WebP подходят; имя и расширение в настройке должны совпадать с файлом, включая регистр букв на хостинге.

## Публикация

Для автоматической публикации на GitHub Pages уже подготовлен `.github/workflows/pages.yml`. **[Полные команды для PowerShell](GITHUB-PAGES.md)**: создание репозитория, включение Pages и дальнейшее обновление через `git push`.

После `npm run build` готовый сайт находится в **`dist/`**. Загрузите **содержимое** этой папки на статический хостинг с HTTPS. Можно разместить его в корне домена или в подпапке, например `/test/`. Для подпапки используйте адрес с завершающим слешем: `https://example.ru/test/`; настройте перенаправление с `/test` на `/test/`, если хостинг не делает этого автоматически.

На сервере должны лежать `index.html`, `site-config.js` и папка `assets` из сборки. Страницы используют адреса после `#`, поэтому отдельные серверные маршруты для результатов не нужны.

**Контакты можно менять без пересборки:** отредактируйте `dist/site-config.js` или уже опубликованный `site-config.js`. Новую фотографию в этом случае положите в опубликованную папку `assets/`. При следующей сборке `dist/` создается заново, поэтому те же изменения сохраняйте в исходных `public/site-config.js` и `public/assets/`.

Для изменения текстов, логики или стилей потребуется повторить `npm run build` и загрузить обновленную сборку. Если после публикации видна старая версия настроек, обновите страницу без кеша и при необходимости очистите кеш хостинга.

Для размещения на Tilda сначала опубликуйте собранный сайт отдельно, затем вставьте его HTTPS-адрес через iframe в HTML-блок. Вставка исходного `index.html` в HTML-блок Tilda сама по себе не переносит приложение и его ресурсы.

| `src/styles.css` | Оформление и адаптация под размеры экранов. Основные цвета заданы в `:root`: `--teal`, `--teal-dark`, `--paper`, `--mint`, `--muted`, `--line`. |

| `tests/content.test.js` | Автоматические проверки логики результата. |

## Логика и данные

Сохранены пять тем исходного теста: возраст, цикл, сон и настроение, телесные симптомы, анализы на гормоны. Тексты переработаны, а суммирование баллов заменено осторожной логикой. Это информационный опрос, не диагностический инструмент и не валидированная медицинская шкала.

Результат о возможной постменопаузе появляется только при возрасте от 45 лет и отсутствии менструаций не менее 12 месяцев, если пользователь не выбрал особые обстоятельства. Изменения цикла до 45 лет, влияние препаратов, беременность, кормление грудью и операции требуют индивидуальной оценки. Выраженные симптомы при привычном цикле также дают неопределенный результат. Ответы об анализах не меняют определяемый этап; симптомы и анализы уточняют объяснения и рекомендации.

Медицинские ориентиры: [NICE NG23](https://www.nice.org.uk/guidance/ng23/chapter/Recommendations) и [NHS — Menopause and perimenopause](https://www.nhs.uk/conditions/menopause-and-perimenopause/). Ссылки доступны и внутри сайта.

Ответы хранятся только в памяти открытой страницы, не отправляются на сервер и сбрасываются после обновления. Cookies и постоянное хранилище для ответов не используются. Кнопка «Поделиться тестом» передает общую ссылку без ответов и результата. «Сохранить результат» создает на устройстве текстовый файл **с выбранными ответами о здоровье** и рекомендациями.

`npm test` проверяет все **1 536 комбинаций** ответов, ограничения для этапов, независимость результата от анализов, персонализацию и обработку некорректных данных. `npm run build` проверяет сборку для публикации. После изменения вопросов или логики запускайте обе команды.

## Выполненные проверки

- Сборка Vite и 14 автоматических тестов проходят без ошибок. Помимо 1 536 комбинаций ответов проверены все 4 096 комбинаций удаления полей врача и контактов.
- В Chromium проверены четыре исхода теста, возврат назад, изменение ответа с пересчетом результата, повторное прохождение, скачивание файла и сброс после обновления страницы.
- Проверены ширины 320, 375, 390, 768 и 1280 px. Горизонтальной прокрутки на проверенных экранах нет.
- Та же проверка пройдена готовой сборкой, размещенной в подпапке `/test/` на обычном статическом сервере. В ходе прохождения нет ошибок JavaScript и внешних сетевых запросов.
- Проверены управление клавиатурой, единые контактные настройки, загрузка и запасной значок фотографии, отправка ссылки без результата и ручное копирование при недоступном буфере обмена.
- Проверены работа без блоков `doctor` и `contacts`, одна и несколько ссылок записи, старое поле `bookingUrl`, скрытие пустых данных, возврат фокуса после закрытия выбора клиники и сохранение ответов при открытии этого окна. Проверка axe-core пройдена и для окна выбора на ширинах 320–1280 px.
- axe-core не обнаружил нарушений WCAG 2 A/AA и 2.1 AA на главной странице, вопросе о цикле, неопределенном результате, странице постменопаузы и странице о данных. Это автоматическая проверка в Chromium, а не сертификация или проверка всех браузеров.

Сценарии браузерной проверки сохранены в `tests/browser-check.js` и `tests/browser-accessibility.js`. Их можно повторить через Playwright CLI при запущенном сайте:

```sh
npx --yes --package @playwright/cli playwright-cli --session=local open http://127.0.0.1:5173/
npx --yes --package @playwright/cli playwright-cli --session=local run-code --filename=tests/browser-check.js
```

Для сценария доступности сначала скачайте `axe-core` через `npm pack axe-core --pack-destination output/reference`, распакуйте `package/axe.min.js` в `output/reference/`, затем запустите такой же `run-code` для `tests/browser-accessibility.js`. Папки `output/reference` и `output/playwright` должны существовать. Скриншоты проверок и архив готовой сборки `output/site-ready.zip` не нужны на хостинге.

Шрифты Lora и Manrope включены в проект по лицензии SIL Open Font License; тексты лицензий находятся в `public/assets/fonts/`. Сборка и обычный запуск не скачивают шрифты из интернета.
